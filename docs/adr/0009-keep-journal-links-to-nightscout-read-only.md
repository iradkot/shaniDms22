# Keep Journal links to Nightscout read-only

In V1, a Product User may explicitly link a Meal Entry or Activity Entry to existing Nightscout records and ShaniDms will re-read their current values, but it never creates, edits, tags, or deletes Nightscout data. Local Journal facts and external Nightscout facts remain separately owned and visibly attributed; a replaceable local cache may retain the last-read external values for offline use, but the backend does not copy the raw source history. Distinct source identities are never deduplicated by time or value, and several external records belong to one real-world Meal Entry only after explicit confirmation; a record without stable external identity may prefill local data but cannot form a durable live link. A missing external record leaves the local entry intact, while transferring an existing link also requires confirmation and supports Undo. This deliberately removes the legacy meal-tag write behaviour and favours clear source ownership over automatic grouping or two-way convenience.
